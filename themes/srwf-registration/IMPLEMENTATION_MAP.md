## Desktop runtime evidence admitted for this repair

Owner diagnostic v0.2.5 established the real opted-in wrapper, the correct Gravity Forms Reset → Foundation → Framework → Orbital → GTB order, an 840px target width, canonical normal-control presentation, a 115px-wide/56px-high real Submit with `--gf-local-width:auto`, title/section headings resolving to `Vazir`, one Tom Select source with 950 options and a 39.5px `.ts-control`, and real GPFUP class structure. These facts are runtime evidence, not design authority.

The same runtime evidence does **not** resolve the production breakpoint, desktop short-field pairing target, desktop shadow, title metrics, rhythm, focus geometry/alpha, helper/error exact sizing, page-shell ownership, or GPFUP crop/upload behavior. Those states remain explicitly unresolved above.

## Activation contract

1. Install/activate the single theme-local plugin entry point in `src/` with its adjacent stylesheet.
2. On the intended SRWF Gravity Form only, set **Form Settings → Form Layout → CSS Class Name** to `srwf-registration-theme`.
3. Keep Gravity Forms as behavioral owner. Configure the form's authentic **Description Placement** and **Validation Message Placement** below inputs and enable **Validation Summary** according to the owner-approved visual contract; this implementation does not reorder or synthesize those states.
4. The plugin selects Orbital only for the opted-in form and enqueues the SRWF stylesheet only while that form is being enqueued.
5. Vazirmatn delivery remains host-owned; this package names the font but does not fetch it from a CDN.

`STATICALLY_PROVEN` in this repository does not mean `RUNTIME_PROVEN` in WordPress/Gravity Forms.
